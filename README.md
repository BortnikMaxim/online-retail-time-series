# Анализ продаж VINTAGE SNAP CARDS

В [ноутбуке](analysis.ipynb) исследую, как подготовить продажи товара **VINTAGE SNAP CARDS** (`StockCode = 21790`) для прогноза на неделю вперёд. Продажи считаю по дням, неделям и месяцам. Сопоставляю покрытие журнала, необычно крупные партии, недельный ритм и изменение уровня. Графики построены в Matplotlib и Seaborn.

## Что получилось

- **Покрытие.** Зафиксировано **14 528 шт. за 374 дня**. В 24 дня у магазина были продажи, а у товара — ноль. Ещё в 69 дней в журнале нет продаж по всему магазину. Эти даты помечены. Для основной диагностики взяты 48 недель без целиком пустой недели и неполных краёв.
- **Частота и рост.** На общем календарном отрезке CV равен 1,61 по дням, 0,72 по неделям и 0,62 по месяцам. Медианный объём на день с продажами магазина вырос во второй половине периода в 2,63 раза. В проверке без трёх крупнейших недель отношение составило 2,49.
- **Пики.** Общий порог Тьюки отметил 32 дня и три недели. Локальное правило на основе медианы и MAD выделило неделю, закончившуюся 31 июля. В ней 431 шт., из них 288 в одном счёте. Сигнал зависит от длины окна. Пики сохранены.
- **Недельный ритм.** STL и ACF указывают на умеренный семидневный рисунок. В 42 сопоставимых неделях сохраняются различия и среди шести активных дней, без субботы. Для перестановок в четырёхнедельных блоках p = 0,0033, размер эффекта небольшой (W Кендалла = 0,089). Короткая история ограничивает выводы о годовых эффектах.
- **Стационарность.** Для исходного недельного ряда ADF даёт p = 0,2741, KPSS — p < 0,01. После первой разности `log1p` результаты согласуются со стационарностью (ADF p ≈ 4,44 × 10⁻⁹, KPSS p > 0,10). Вывод сохраняется при других лагах KPSS и нормировке на активные дни. Модель с явным трендом на логарифмической шкале остаётся обоснованным вариантом для дальнейшего сравнения.

## Как воспроизвести

Из корня проекта, с Python 3.11:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m jupyter lab analysis.ipynb
```

В JupyterLab выберите **Restart Kernel and Run All Cells**. При первом запуске официальный XLSX загружается в `data/`. Если автоматическая загрузка недоступна, скачайте с UCI файл `Online Retail.xlsx` и положите его в `data/` под исходным именем. При загрузке проверяется контрольная сумма.

Из терминала ноутбук можно выполнить так:

```bash
python -m jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=240 analysis.ipynb
```

[retail_ts.py](retail_ts.py) содержит функции анализа. [retail_plots.py](retail_plots.py) содержит функции визуализации. Результаты и графики сохранены в ноутбуке.

Данные — Daqing Chen (2015), [Online Retail](https://doi.org/10.24432/C5BW33), UCI Machine Learning Repository, CC BY 4.0.
